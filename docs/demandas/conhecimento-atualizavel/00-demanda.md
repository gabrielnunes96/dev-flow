# Demanda original (19/11/2026)

> A tecnologia todo dia melhora, se atualiza, temos coisas novas. Mas nem sempre atualização é coisa boa — sempre espera sair a versão LTS, que é a mais estável. Nossos agentes (o especialista, o arquiteto, o designer, todo mundo) um dia podem ficar com a habilidade que a gente cadastrou obsoleta. O que seria plausível fazer para tornar os nossos agentes automaticamente mais inteligentes, do tipo deles se atualizarem? Não sei se é um MCP que sempre atualiza eles, que sempre deixa eles cientes de novas coisas, para não ficar para trás. Daqui 3 meses as regras mudam, temos novas IAs, mais possibilidades de melhoria, e o bot fica defasado. É uma coisa que eu não queria ter que me preocupar, em estar sempre atualizando os workers do nosso plugin. Eles teriam que ser auto-atualizáveis, igual uma pessoa que está sempre estudando as novas tecnologias de mercado.
>
> Mas só porque está aprendendo coisa nova não quer dizer sair aplicando. É saber ler os padrões do código em que está sendo iniciado, entender como as regras funcionam, para aí sim atacar seguindo os padrões. A não ser que seja algo novo — aí a gente pode ir definindo.

Proposta aceita pelo usuário (camadas 1 a 4): separar método de conhecimento volátil; consultar a documentação da versão em uso com o projeto em primeiro lugar; revisão periódica por PR com aprovação humana; testes de comportamento antes de aceitar atualização. Seguir o próprio fluxo (funcional → técnica → plano → tarefas). Aprovações delegadas pelo usuário nesta sessão ("você está livre para fazer o que quiser").
